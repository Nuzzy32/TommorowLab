# Verifikasi simpan/muat lokal TomorrowLab — 28 Oktober 2026

Scope: WP-09, yaitu simpan, muat dan hapus konfigurasi lokal (PRD FR-21–23, NFR-12–13; USER_FLOW UF-12–13; ARCHITECTURE §10; DESIGN_SYSTEM CMP-12), plus preferensi "bantuan sudah dilihat". Bukti lokal di Chromium; browser wajib lain belum diuji.

## Keputusan implementasi

- **Record:** `src/storage/scenarios.ts` menyimpan satu key `tomorrowlab:scenario:<recordId>` dengan isi berikut, ukuran ≤100 KB UTF-8, tanpa key indeks:
  - `{schemaVersion:1, recordId, revision, savedAt, config, versions}`;
  - ID baru dibuat dengan `crypto.randomUUID()`, bukan seed model.
- **Daftar:** dibentuk dari enumerasi namespace, lalu setiap record divalidasi (`validateConfig`, versi schema/model/RNG, kecocokan recordId dan key, revisi, waktu).
  - Record rusak berstatus `invalid` dan record dengan versi berbeda berstatus `unsupported`.
  - Keduanya tetap terlihat dan hanya bisa dihapus manual; tidak pernah dimuat sebagian atau diperbaiki diam-diam.
  - Batas 10 slot menghitung juga record yang rusak.
- **Mutasi:** setiap simpan dan hapus mengikuti urutan berikut.
  1. Mengambil Web Lock eksklusif `tomorrowlab:scenario-write:v1`.
  2. Membaca ulang target dan membandingkannya dengan nilai mentah yang dilihat pengguna saat dialog dibuka (compare-and-swap).
  3. Menjalankan satu `setItem` atau `removeItem`.
  4. Melakukan readback.

  Hasilnya dipetakan sebagai berikut:
  - konflik → "Data tersimpan berubah di tab lain";
  - exception tulis → "Konfigurasi belum tersimpan; browser menolak penyimpanan";
  - readback tidak cocok → "Status penyimpanan belum dapat dipastikan".

  Event `storage` hanya menyegarkan daftar dan menandainya berubah; ia tidak menggantikan lock.
- **Degradasi:** tanpa localStorage (akses dilempar atau diblokir) atau tanpa Web Locks, tombol simpan/hapus dinonaktifkan dengan alasan. Run tetap berjalan di memori, dan record yang masih terbaca tetap bisa ditinjau.
- **UI:**
  - Header punya tombol **Tersimpan** yang membuka drawer berisi:
    - nama sebagai teks, ringkas dua baris;
    - waktu simpan lokal;
    - ringkasan loket/λ/pelayanan/durasi/seed dan jumlah jadwal;
    - tombol Muat/Hapus.
  - **Simpan konfigurasi** tersedia di drawer dan di panel Hasil final, dengan isi dialog:
    - nama 1–60 karakter (fokus awal, default "Kantin · N loket");
    - sumber yang disebut jelas: draft atau snapshot run;
    - opsi menyertakan tambahan pelanggan run sebagai jadwal gabungan;
    - pilihan "Perbarui konfigurasi ini" atau "Simpan sebagai baru" untuk konfigurasi yang sedang dimuat;
    - pilihan slot pengganti bila 10 slot penuh.
  - Mengganti slot selalu lewat konfirmasi "Ganti konfigurasi tersimpan?".
  - Muat selalu lewat konfirmasi (fokus awal Batal) dan membuka READY pada 00:00 dengan nilai tersimpan. Run lama diganti, bukan dilanjutkan. Saat perbandingan A/B berjalan, muat ditolak dengan permintaan membatalkan batch dulu.
  - Hapus selalu lewat konfirmasi yang menyebut nama slot. Fokus pindah ke slot tetangga atau ke judul daftar kosong.
- **Preferensi bantuan:** bantuan ringkas tidak muncul lagi setelah ditutup sekali (`tomorrowlab:pref:help-seen`). Key ini berada di luar namespace slot, jadi tidak dihitung sebagai slot.
- **Belum disertakan:** kontrol "hapus seluruh data TomorrowLab" (opsional di ARCHITECTURE §10.2), dan menyimpan langsung A/B dari tab Bandingkan.

## Pemeriksaan visual

Browser pane 1440×1000: drawer kanan berisi deskripsi penyimpanan lokal, tombol simpan, dan kartu slot dengan nama literal; pesan sukses muncul setelah readback.

## Batas yang diketahui

- Hanya Chromium yang diuji. Safari/Firefox (Web Locks, mode privat, kuota) masuk WP-10.
- localStorage bukan cadangan; data hilang bila browser dibersihkan. Web Locks hanya menyerialkan tab TomorrowLab yang bekerja sama.
- Hasil run dan hasil perbandingan tidak disimpan; hanya konfigurasi.
